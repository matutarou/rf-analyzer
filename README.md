# 自治体データ ランダムフォレスト回帰分析ツール

## 保存・診断・AI補助

- **品質・前処理**: 変数を選択後、欠損による除外行、定数列、重複、数値らしい文字列、無限値、カテゴリ変換を確認します。「前処理を確認しました」を選ぶと分析可能になります。重複は自動削除しません。
- **変数間の関係**: 数値列のPearson相関とペアごとの有効件数を表示します。最大40変数。カテゴリ列は対象外、定数列や有効件数不足は計算不可です。未選択時は先頭40数値列を対象とします。
- **保存・履歴比較**: 分析成功時に履歴を自動保存。保存ボタンでは途中の作業やAI解説を含めた別の記録を保存します。最大4件の精度・変数・設定・重要度を比較できます。データや目的変数、除外行が違う場合は警告します。
- **再開**: フォルダアイコンで元データ・変数選択・設定・結果・保存時のAI解説を復元します。学習済みモデルと別途アップロードしたテストデータは保存しないため、予測には再分析と必要に応じたテストデータの再読込が必要です。
- **レポート**: 履歴のダウンロードアイコンから印刷用HTMLを開きます。分析条件・評価値・重要度・SHAP・前処理件数・保存時のAI解説を収録します。ブラウザの印刷からPDF保存できます。
- **画面連動の質問**: 診断・相関・評価指標の質問アイコンでチャットへ移動し、質問と参考情報をセットします。送信はユーザー操作です。送信前に添付情報を確認・解除できます。
- **3視点の整理**: 3視点解説を生成後、「共通点・相違点を整理」で追加のLLM呼び出しを行います。多数決ではなく、事実・評価の違い・未確認事項を整理します。
- **回答評価**: チャット・各役割・整理結果の評価ボタンから補足付きで記録できます。「回答評価」タブで直近200件を確認できます。評価を記録してもモデルの自動学習は行いません。

保存先は `backend/data/workspace.sqlite3` です。元データと評価コメントが平文で保存されるため、機密資料の取扱いに注意してください。APIキーの入力欄はプロジェクト保存対象ではありません。ローカル少人数向けで、ユーザーごとのアクセス制御はありません。

検証用の架空データ: `backend/fixtures/workspace_demo.csv`。
全回帰テスト: `cd backend` の後、`venv/bin/python -m unittest test_improvements test_workspace -v`。
LLM連携は既存の [Chat Completions API](https://developers.openai.com/api/reference/resources/chat) を使用します。

## 分析・AI機能の更新

- AI解説とチャットは現在のLOOCVのR²を参照し、未提供の指標を0として扱いません。
- 3視点解説は事実・解釈・追加検証を区別し、重要度を因果効果として断定しないよう指示しています。
- RAGはコサイン類似度0.4以上を検索候補とする暫定設定です。実資料で適合率を確認して調整してください。候補の表示は回答の正しさを保証しません。
- PDFのページ番号は新規登録時に記録します。既存資料は再登録するとページ表示が有効になります。Word・テキストおよび旧資料は部分番号と本文を表示します。
- 画面の分析はバックグラウンドジョブで実行し、進捗確認とキャンセルができます。キャンセルは学習の区切りで反映され、現在実行中の学習やSHAP計算は即時停止しません。
- 分析ジョブは同時1件、保持は最大10件です。サーバー再起動で消えます。従来の `/api/analyze` は同期応答互換のまま残しています。
- 木の数は最大500、最適化試行数は最大100です。評価方式自体は変更していません。

回帰テスト: `cd backend` の後、`venv/bin/python -m unittest test_improvements -v`。

自治体が公開するCSV/Excelデータをアップロードし，ランダムフォレスト回帰で分析するWebアプリケーションです．

## セットアップ

### 前提条件

- Python 3.10 以上
- Node.js 18 以上

### 1. バックエンド

```bash
cd backend

# 仮想環境の作成（推奨）
python -m venv venv
source venv/bin/activate   # Windows: venv\Scripts\activate

# パッケージインストール
pip install -r requirements.txt

# 起動
python main.py
# → http://localhost:8780 で起動
# → API ドキュメント: http://localhost:8780/docs
```

### 2. フロントエンド

```bash
cd frontend

# パッケージインストール
npm install

# 開発サーバー起動
npm run dev
# → http://localhost:5280 で起動
```

ブラウザで `http://localhost:5280` にアクセスしてください．

### ポートの変更

- `RF_BACKEND_PORT`（既定: `8780`）: バックエンドの待受ポートとViteのAPIプロキシ先。
- `RF_FRONTEND_PORT`（既定: `5280`）: Vite開発サーバーのポートとバックエンドのCORS許可オリジン。

環境変数は起動するターミナルで設定してください。バックエンドとフロントエンドの両方のターミナルで、同じ `RF_BACKEND_PORT` を指定する必要があります。`RF_FRONTEND_PORT` を変更する場合も、CORS設定を合わせるため両方で同じ値を指定してください。

```bash
# バックエンドのターミナル（backend ディレクトリ）
RF_BACKEND_PORT=9000 python main.py

# フロントエンドのターミナル（frontend ディレクトリ）
RF_BACKEND_PORT=9000 npm run dev
```

ポートには1〜65535の整数を指定してください。不正値では起動に失敗します。Viteは指定ポートが使用中の場合もエラーになり、別ポートへ自動変更しません。

## 使い方

1. **データ読込**: CSV/TSV/Excelファイルをドラッグ＆ドロップ
2. **カラム選択**: 目的変数（数値型）と説明変数を選択
3. **パラメータ**: ハイパーパラメータを設定（デフォルト値でもOK）
4. **分析結果**: R²，RMSE，MAE，特徴量重要度，実測vs予測プロット等を確認

## 主な機能

- CSVのエンコーディング自動判定（UTF-8, Shift_JIS, CP932, EUC-JP）
- カテゴリ変数のラベルエンコーディング
- Train/Test分割 + 交差検証
- 過学習警告の自動表示
- 特徴量重要度の可視化
- 実測値 vs 予測値の散布図
- **AI解説（役割別）**: 結果を賛成・中立・反対の3視点で並列解説
- **対話アシスタント（RAG）**: 機能や統計指標（R²・SHAP等）の質問に、知識ベースと現在の結果を根拠に回答
- **知識ベース管理**: PDF/Word/テキストを登録し、アシスタントの回答根拠にする（OpenAI埋め込み + ローカル保存）

## API エンドポイント

### 分析履歴と自動保存

- 左上の履歴ボタンでサイドバーを開き、分析を切り替えられます。「新しい分析」は独立した履歴を作ります。
- データ、選択途中の変数、パラメータ、分析結果、AI解説、チャットと入力途中の文章、添付情報、AIタブ、パネル幅とパネル内スクロール位置を同じ履歴に自動保存します。
- 編集後約0.6秒で保存を開始します。画面上部の「保存済み」を確認してください。保存前に閉じる場合はブラウザの警告対象になりますが、ブラウザの強制終了・端末の電源断まで保証するものではありません。
- 履歴切り替え前には保存を完了させます。通信エラー時や分析・AI生成中は切り替えを中止します。複数タブの競合時は古い内容で上書きせず、別名保存で変更を残せます。
- サイドバーのごみ箱で履歴を削除できます。削除は取り消せません。チャットのリセットはその履歴の会話・下書き・添付だけを消し、分析設定と結果は残します。
- チャットは最新40件から表示し、過去分は追加表示できます。LLMに渡す会話履歴は直近12件です。CSV・変数・分析設定の変更時は古い画面情報の添付を解除します。
- 新しい保存形式では、読み込み済みデータの浮動小数点値と列の型を保持します。旧形式の履歴も開けますが、過去に丸められた値は元のCSVから読み込み直す必要があります。
- 保存先は `backend/data/workspace.sqlite3` です。APIキーは履歴に保存せず、従来通りブラウザで管理します。
- 学習済みモデル、カテゴリ変換ルール、説明変数の順序、実際に使った学習パラメータも履歴に保存します。新しく分析した履歴は、アプリの再起動後も再学習せずシミュレーションできます。テスト予測の一時的な画面状態は保存対象外です。
- モデル未保存の旧履歴は一度再分析してください。データ・目的変数・説明変数・学習設定が変更された場合、古いモデルをその履歴に引き継ぎません。
- モデルは `skops` 形式で同じSQLiteファイル内に保存します。モデルファイルのアップロード機能はなく、未知の型を自動的に信頼しません。破損やPython・scikit-learn・NumPy・SciPy・skopsのバージョン不一致時はモデルを使わず、分析結果だけを復元して画面に通知します。
- 別名保存した履歴は同じモデルを共有し、最後の参照履歴を削除するとモデルも削除されます。バックアップはアプリ停止中にSQLiteファイルをコピーしてください。

### 履歴API

| メソッド | パス | 説明 |
|---------|------|------|
| GET | `/api/projects?compact=true` | サイドバー用の履歴一覧 |
| PUT | `/api/projects/{id}` | `expected_version` を用いた作成・更新 |
| POST | `/api/projects` | 別名保存 |
| POST | `/api/projects/{id}/restore` | 作業状態とデータの復元 |
| DELETE | `/api/projects/{id}` | 履歴削除 |

### 分析・AI API

| メソッド | パス | 説明 |
|---------|------|------|
| GET | `/api/health` | ヘルスチェック |
| POST | `/api/upload` | CSVアップロード |
| POST | `/api/analyze` | RF回帰分析の実行 |
| POST | `/api/predict` | 単一データの予測 |
| POST | `/api/explain` | 分析結果のAI解説（単発） |
| POST | `/api/explain/roles` | 分析結果を賛成・中立・反対の3視点で解説 |
| POST | `/api/assistant/chat` | RAG付き対話アシスタント（機能・指標の質問応答） |
| POST | `/api/knowledge/ingest` | 知識ベースへドキュメント登録（PDF/Word/テキスト） |
| GET | `/api/knowledge/list` | 登録済みドキュメント一覧 |
| DELETE | `/api/knowledge/{doc_name}` | 知識ベースからドキュメント削除 |
